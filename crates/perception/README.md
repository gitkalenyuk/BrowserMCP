# bmcp-perception

Turns the Chrome accessibility tree (CDP `Accessibility.getFullAXTree`) into a compact
text snapshot an LLM can read, with refs it can act on. Pure Rust, no CEF: input is the
`serde_json::Value` CDP returns.

## Format

```
snap 7 tab=3 "Sign in – Acme" https://acme.com/login vp=1280x720 y=0/1840
- banner
  - link "Home" @7:e1
- main
  - heading "Sign in" h1
  - textbox "Email" @7:e2 req focused
  - textbox "Password" @7:e3 pwd
  - checkbox "Remember me" @7:e4 off
  - button "Sign in" @7:e5 disabled
  - list "Providers" 12 items, 3 shown → @7:g1
    - button "Google" @7:e6
- footer (collapsed, 3 refs) → @7:g2
```

* **Header**: `snap <id> tab=<tab> "<title>" <url> [vp=WxH] [y=scroll/height] [mode=full|skeleton:N] [root=<ref>]`.
* **Lines**: `- <role> "<name>" [@S:eN] [states...]`, indented 2 spaces per level.
* **Refs** only on interactive nodes: button, link, textbox, searchbox, combobox, listbox,
  option, checkbox, radio, switch, slider, spinbutton, tab, menuitem*, treeitem, summary,
  and focusable "click-ish" nodes (a `<div tabindex=0>`, unless it contains other controls).
* **States** (fixed order): `h1`..`h6`, `="value"` (max 40 chars) or `pwd`, `on`/`off`/`mixed`,
  `pressed`, `expanded`/`collapsed`, `selected`, `req`, `disabled`, `readonly`, `invalid`,
  `focused`, `offscreen` (only with layout info).
* **Roles** are CDP roles, with a few aliases: `contentinfo`→`footer`,
  `complementary`→`aside`, `navigation`→`nav`, `StaticText`→`text`, `image`→`img`,
  `LabelText`→`label`, `MenuListPopup`→`listbox`, `DisclosureTriangle`→`summary`.
* **Names** are whitespace-collapsed and cut to 80 chars (`…`); `"` is escaped as `\"`.
* **Passwords**: the value is never printed nor searched; the field shows `pwd`.
  Detection: DOM hint `NodeLayout::input_type == "password"`, a `protected` property,
  a value of only `•`, or a name containing "password" (several languages).

### Modes

| Mode | Shows |
|---|---|
| `Interactive` (default) | controls + headings, alerts, dialogs + landmarks/lists/forms that contain them. Text, images, unnamed wrappers dropped. |
| `Full` | also text and images; wrappers still flattened, label text that repeats a control's name dropped. |
| `Skeleton { depth }` | interactive content `depth` levels deep; deeper subtrees become `(collapsed, N refs) → @S:gN`. |

* Lists (list, listbox, menu, tree, table, grid, feed, tablist) with more than
  `collapse_lists_over` (8) children show `collapse_show` (3) of them plus `→ @S:gN`.
* Over `max_chars` (6000 ≈ 1500 tokens) the snapshot falls back to skeleton depth 3, 2, 1
  and adds a `! ... over the budget ...` line; if even depth 1 is too big, lines are cut
  and the last line says `… cut to fit`.
* Drill-down: `root = "@7:g1"` (a group) or `"@7:e3"` (an element) renders only that
  subtree; a list used as root is never collapsed.

### Refs

* `@S:eN` – element. N is stable per `backendDOMNodeId` for the whole document, so
  `@7:e3` and `@8:e3` are the same node. Bare `e3` means "latest snapshot".
* `@S:gN` – group (collapsed part of snapshot S), only for `root=`.
* After `RefRegistry::new_document()` (call it when the page navigates) old refs give
  `STALE_REF`. Numbers keep increasing across documents, so an old `e3` never silently
  points at a new node.

### Diff

```
diff 1→2: + alert "Wrong password" | ~ @2:e3 textbox "Password" invalid focused | ~ @2:e5 button "Sign in" enabled | - dialog "Cookies"
```

`+` added, `~` changed (new states; a removed state prints its opposite: `enabled`,
`valid`, `blurred`... or `-state`), `-` removed (only the top-most removed node).
Nodes are matched by `backendDOMNodeId`; compare snapshots taken with the same options.

## API

```rust
let tree = AxTree::from_cdp(&cdp_result)?;          // + .with_layout(map) optionally
let mut registry = RefRegistry::new();               // one per tab
let snap = snapshot(&tree, &mut registry, &SnapshotOptions::default(), header)?;
snap.text;                                           // for the model
snap.refs;                                           // Vec<RefEntry { ref_str, backend_node_id, role, name }>
let backend_id = resolve(&registry, "@7:e3")?;       // or "e3"; StaleRef / BadRef
let group = resolve_group(&registry, "@7:g1")?;      // GroupTarget for drill-down
let hits = find(&tree, &mut registry, &Filter { text: Some("sign in".into()), ..Default::default() }, 10)?;
hits.to_text();                                      // "find 9: 1 of 1 matches\n- button ..."
let line = diff(&prev_snap, &next_snap);
registry.new_document();                             // on navigation
```

Errors (`PerceptionError::code()`): `BAD_REF`, `STALE_REF`, `NOT_FOUND`, `BAD_FILTER`, `BAD_TREE`.

## Tests

Fixtures are in `tests/fixtures/cdp/` at the repo root (generated by
`tests/fixtures/cdp/gen_fixtures.py` to mimic real Chrome output; replace with real dumps
when `--dump-ax` exists). Golden outputs are `insta` snapshots in `tests/snapshots/`;
after an intended format change run `cargo insta review` (or `INSTA_UPDATE=always cargo test -p bmcp-perception`).
